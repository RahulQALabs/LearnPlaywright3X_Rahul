# workflow
- When asked to create notes/content for a new chapter that should follow an existing project pattern, prefers that the agent first explore and review the existing notes files across other chapters to infer the format, structure, and conventions — then replicate that pattern faithfully — rather than being told the format explicitly. Confidence: 0.9
- For interview/study notes, use the standard 10-requirement format: (1) 2-3 line intro, (2) interview Q&As from basic to advanced — default 10, but go beyond if the topic is large and more questions fit naturally, (3) well-structured beginner-friendly explanation, (4) comparison tables wherever applicable, (5) real-world and code examples, (6) step-by-step execution flow with pipeline diagram, (7) interview tips, common mistakes, and key takeaways, (8) proper Markdown formatting with headings/tables/code blocks, (9) concise and revision-friendly, (10) comprehensive coverage without missing any questions. Confidence: 0.95
- When user provides a list of questions/topics and asks to create an md file "as it is", preserve the list as-is without expanding each item into full code solutions or implementations. Confidence: 0.65
- When appending new content to existing markdown study/notes files, preserve all existing points and content format — do not overwrite or remove old content. Confidence: 0.8
- When providing an alternative solution or refactored logic, prefers a new separate file rather than modifying the original source file — keeps original code intact and side-by-side for comparison. Confidence: 0.9
- After creating or modifying project files, prefers the agent to commit and push the changes to the configured GitHub remote automatically (using `git add`, `git commit`, `git push`) rather than leaving changes uncommitted locally. Confidence: 0.85
- Prefers the same educational notes-and-interview-questions template/format to be replicated across different projects (e.g., from a JavaScript/Playwright project to a Core Java project) — the detailed notes file + separate interview questions file pattern is a reusable template he expects applied to new learning repos in any language. Confidence: 0.7
- For answer/solution files accompanying interview questions, prefers answers written in plain conversational English with real code examples — explicitly avoids "bookish" or overly formal/academic language. Confidence: 0.8
- For educational notes and examples, prefers practical, test-automation-focused language and real-world testing scenarios over academic/theoretical phrasing — explicitly requested "language should be practical" (e.g., default params tied to `launchBrowser()`, callbacks tied to Playwright waits, closures to test-data generators). Confidence: 0.9
- For answer/solution files, prefers answers to be brief — maximum 2-3 lines per answer — rather than lengthy explanations. Confidence: 0.8
- When asked whether their learning coverage of a topic is sufficient (e.g., "is this enough or need more topics?"), expects an honest, structured gap assessment — what's covered, what's missing, and a prioritized recommendation of which missing topics matter most for their goals (interview prep / test automation) — not a generic or purely reassuring answer. The check should extend beyond the current chapter/folder: the user explicitly follows up to confirm "nothing is pending beyond this folder's topic," expecting the agent to cross-reference the course roadmap / practice files (e.g., `js-basic-practice-programs.md`) and name concrete pending chapters (e.g., Objects, ES6, higher-order functions) rather than only confirming the current topic is done. Confidence: 0.75
- For programming practice files, prefers each program laid out in HackerRank-style sections: **Problem Statement → Input Format → Output Format → Sample Input → Sample Output → Solution** — explicitly requested ("like hackerrank") with the description first, then input/output formats, then sample I/O, then the code, matching a reference screenshot the user provided. This refines the earlier simpler "input/output type + example" annotation style. Confidence: 0.9
