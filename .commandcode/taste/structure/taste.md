# structure

- For educational/revision chapter folders, prefers a dedicated interview questions file (e.g. `Interview_Questions_Topic.md`) separate from the main notes file — following the convention where each chapter has its own interview question file alongside the topic notes. Confidence: 0.7
- Prefers consistent project structure across all chapter/module folders — every chapter should follow the same folder and file organization pattern (e.g., all should have an `IQ_Notes` folder with notes and interview questions). If a new chapter is missing this structure, the user expects it to be created to match the established pattern. Confidence: 0.85
- For interview questions files, prefers a companion `solution.md` file containing the answers — written in conversational English with examples, separate from the questions file. Confidence: 0.8
- For interview question files, prefers questions organized by difficulty levels (Easy / Medium / Hard sections) rather than a flat list — explicitly requests "arrange easy, medium, hard". Confidence: 0.9
- For learning/revision topics, prefers a three-file pattern: detailed notes file + interview questions file + a separate programming practice file with programs split into Easy/Medium/Hard sections (e.g. `Program_missing.md`), so theory, Q&A, and coding practice each live in their own file. Confidence: 0.85
